# 架构与生命周期

当前交付一个 `ExplorerExtensions.exe` 和一个 `ExplorerExtensions.dll`，两个功能共用设置、登录启动项、加载器、会话验证、日志和工作线程。历史独立版仅保存在 `releases/`。

## 模块边界

| 文件 | 职责 |
| --- | --- |
| `src/host.cpp` | 无参数设置窗口、按功能命令行、当前用户配置、旧版迁移、唯一后台加载器 |
| `src/dllmain.cpp` | 最小 DllMain、消息钩子导出、进程宿主互斥、功能协调线程 |
| `src/features/drive-navigation/` | 原有 Shell 导航枚举过滤与 COM 包装器 |
| `src/features/desktop_popup.cpp` | 两种明确包含 this 的 x64 回调、原始调用转发、一次安装和原子启停 |
| `src/module_identity.cpp` | 已加载 PE 的 RSDS GUID/Age/镜像大小与可执行区检查 |
| `src/symbol_resolver.cpp` | 仅 EXE 辅助进程使用：WinHTTP 下载匹配 PDB，DbgHelp 精确核对和完整签名定位 |
| `src/symbol_client.cpp` | Explorer 中启动辅助进程，通过仅继承指定句柄的管道接收结果并重新核对模块身份 |
| `src/diagnostics.cpp` | OS/模块版本、PID、签名、API 结果日志；不读取桌面名称或应用内容 |

后续同一宿主的功能放在 `src/features/`，经 `features.h` 接入协调线程。公共能力保持功能无关；真正独立交付的扩展才新增 `extensions/<extension>/`。

## 配置与线程

设置写入以及协调线程/后台加载器的设置读取使用同一个当前用户、当前会话命名互斥体。命令行单项修改在持锁状态重新读取其他功能开关，避免并发修改丢失其他设置。后台加载器的最终退出判断与互斥体释放也在设置锁内，避免快速停用/启用时丢失加载器。

消息回调在没有工作线程时读取配置、固定 DLL 映射并排队工作，不下载符号、不等待设置锁。协调线程以 100ms 周期更新功能请求；桌面提示的耗时初始化使用另一工作项。安装与状态切换通过 SRWLOCK 串行，桌面提示回调只读原子开关和已发布的原始函数指针，不加锁、不访问注册表、不写逐次事件日志。

符号初始化使用代次编号取消过期任务；同一代失败不会循环重试，用户关闭后重新开启才重试。禁用命令等待已加载 Explorer 的停用状态，超时明确失败。重复开启成功的 Hook 不再次安装。每个 Explorer 另有按 PID 和进程启动时间区分的宿主互斥体，阻止不同目录的重复宿主同时安装。

## 符号隔离

DbgHelp 位于同一 EXE 的内部 `--resolve-popup` 辅助进程，Explorer DLL 不导入 DbgHelp 或 WinHTTP，避免与其他扩展在 Explorer 中并发使用全局符号状态。辅助进程最多等待 180 秒；禁用/代次变更会取消，只终止本项目创建的辅助进程，不终止 Explorer 线程。

缓存路径包含 GUID 与十六进制 Age。每次新安装都从匹配 PDB 重新确认完整函数签名，不持久缓存 RVA。只有唯一的已确认函数地址、匹配 GUID/Age/镜像大小和可执行区检查均通过后，才能创建 MinHook。辅助进程返回的是模块相对地址，Explorer 再按其实际已加载模块基址定位，不跨进程复用绝对地址。

## 安全驻留与卸载

首次排队协调工作前，通过 `GET_MODULE_HANDLE_EX_FLAG_PIN` 固定 DLL。已安装入口和跳板保留到 Explorer 退出；停用只切换为原始调用转发，不释放代码。驱动器枚举包装器也可能长期存活，故同样保留代码。

零活跃回调不能证明没有线程已经取得入口地址；本项目不据此强制卸载。退出协调线程时记录活跃回调数、初始化状态和延迟卸载原因。不在 DllMain 中移除 Hook、等待回调、下载符号或销毁复杂资源。

更新、移动 DLL 或变更已加载版本需要用户先全部停用，再手动重启 Explorer。项目不会为了更新自动终止 Explorer。文件移动后的新入口会更新单个启动项；不同目录的宿主检测到已有拥有者时跳过安装并提示重启，而非叠加功能 Hook。
